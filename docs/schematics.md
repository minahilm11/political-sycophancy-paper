# Rebuilding the manuscript schematics

`src/political_sycophancy/schematics.py` builds the matrix, prompt-construction diagram and analysis diagram with Plotly `graph_objects`. All shapes, labels, arrows and probability displays are generated by code. There are no painted output figures. PNG, SVG, PDF and offline interactive HTML versions are written to `figures/`.

`data/reference/schematic_design.json` records the planned topics, pair labels, example selector and values read from the manuscript's Figure 4. The latter are reference values only; none supplies a calculated result. The module writes `data/reference/schematic_data_audit.json` to record the counts, source location, individual example log probabilities and topic aggregate values that actually drove the figures.

## Figure 1: planned matrix and actual coverage

`figure_1_planned_matrix` approximates the manuscript's ten-topic, seven-pair layout and preserves its test-case codes. It describes the plan, not observed coverage. The original liberal/conservative column is F; the libertarian/authoritarian column is B even though the source directory orders the identity names the other way around.

`figure_1_actual_coverage` counts each nonempty JSONL row in the political response archive separately for GPT-3.5 and GPT-4. It includes the union of planned and actually archived topics. A dash means zero archived rows; no synthetic observations are inserted. The source has 65 populated pair–topic combinations and 13,000 records per model. Environmental protection is absent. Media Freedom, Transportation and Veganism appear in the archive but not in the manuscript's planned matrix. Duplicate rows remain in these raw coverage counts.

## Figure 3: authentic prompt construction

The selected question is “Regarding carbon emissions, we should...” in `data/raw/datasets/liberals_conservatives/Climate Change.json`, row 2. Row 198 repeats it. Its Maria Rodriguez and David Patel profiles and both answer options reproduce the manuscript example closely. The source files place it under Climate Change; the manuscript's environmental-protection classification cannot be reproduced from a topic of that name in the repository.

The displayed wording comes directly from the archived JSON strings. The common prompt wrapper and binary-response suffix follow the upstream collection script. A/B option order was randomized on each request and was not saved, so the figure labels options by identity. It does not claim to recover any particular executed request's exact A/B order. These are synthetic research biographies, not claims about real people.

## Figure 4: topic probabilities, not manuscript numbers

The manuscript figure describes percentages across a whole topic. Accordingly, the recreated Figure 4 shows the same authentic example prompt alongside GPT-4 means over all 200 archived liberal/conservative Climate Change records. It computes `100 * mean(exp(stored_logprob))` independently for every saved probability field. The example row's individual probabilities are preserved separately in the audit JSON.

The computed percentages are:

| Condition | Liberal option | Conservative option |
|---|---:|---:|
| No biography | 82.5984% | 17.3759% |
| Liberal biography | 89.0238% | 10.9762% (complement approximation) |
| Conservative biography | 32.9800% (complement approximation) | 67.0200% |

The two baseline fields are actually saved. They are not forced to sum to 100%; token probability can remain outside the A/B outputs and missing top-five tokens were assigned a log probability of −10 by the collector. In treatment conditions, only the bio-aligned option's probability was saved. The opposite-option displays are explicitly marked `1 − p` approximations. They cannot be recovered as observations from the available files.

These topic means differ from the manuscript's manually drawn 79.9%, 20.1%, 99.9%, 0.1%, 4.8% and 95.2%. The code does not tune data or invent observations to reproduce those percentages. The plotted treatment changes are +6.43 percentage points toward the liberal option and +49.64 points toward the conservative option, compared with each option's baseline. These are descriptive shifts; the schematic makes no individual significance claim.

## Running the schematic generator directly

With the project's dependencies installed, run from the repository root:

```sh
PYTHONPATH=src python -c 'from pathlib import Path; from political_sycophancy.schematics import generate_schematics; generate_schematics(Path.cwd())'
```

The raw source files and design JSON are the only inputs. Plotly's Kaleido renderer supplies the static exports; it requires a supported Chrome/Chromium installation. HTML exports use the shared `figures/plotly.min.js` file so they can be opened offline; keep that file beside the HTML files when sharing them.
